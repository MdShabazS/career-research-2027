# Resume — Fresher-Realistic Benchmark (India)

Calibrates the elite patterns down to what is real and effective for a final-year B.E./B.Tech student. This is the standard the candidate is actually measured against.

## 1. Section order that works for freshers
- `[FACT, High]` For students/new grads, **Projects is a first-class section**, and Skills is parsed early. Strong CGPA is an asset but projects out-signal it on a technical resume. (beamjobs, projectstudy, careerskraft.)
- `[REC, High]` Order: **Summary → Technical Skills → Experience (internships) → Projects → Education → Leadership/Activities → Certifications.** Experience above Projects because named-brand internships (Nokia, iHelp) are the highest-credibility anchor a recruiter looks for.

## 2. Projects section (the decisive part)
- `[FACT, High]` **3–5 projects, quality over quantity**; 2–4 strong ones beat many weak ones. Each: title, tech stack, 2–3 bullets = what it does, what you built, a metric if one exists. **A GitHub link is a strong differentiator.** (resumevera, professionalresumefree, careerskraft.)
- `[FACT, High]` Final-year/major projects with a real build, dataset, or measurable outcome are especially valuable. (projectstudy.)
- `[FACT, High]` Recruiters' fast first scan checks three things: **job relevance, tool/software fit, and evidence the skills were applied** in projects/internships. (careerskraft.)

## 3. Fresher honesty calibration
- `[FACT, High]` Embedded-fresher guidance: lead with a **specific specialization statement**, name tools explicitly ("STM32, Keil, FreeRTOS, CAN (PCAN), AUTOSAR fundamentals"), and only claim tools actually used. (piestsystems.)
- `[INFER, High]` For this candidate, honest quantifiers already exist in the reference repo (2 video sources, 6+ functions, 3-state FSM, ~400 images/6 classes, ~93% *reported*, 3-member team). These are the metrics to use — nothing invented.

## 4. Common fresher mistakes to avoid
- `[INFER, High]` Listing 20+ skills with no project backing; "familiar with" tool dumps; presenting team/demo work as solo/production; claiming skills at a level a screen would break (the reference-repo audit already flagged I2C/Cortex-M4 listed as skills against the candidate's own policy); one generic resume for every role instead of light per-JD tailoring.

## 5. Tailoring
- `[FACT, High]` Make targeted versions by changing **summary, skill order, and project bullets** per role — improves ATS match and relevance. Never change facts/dates/ownership between versions. (professionalresumefree, resumevera.)
