# Project Quality Framework

A ladder to grade any project by how much credibility it adds to the four assets. From the brief: Tutorial → Demonstration → Strong portfolio → Industry-credible.

## The ladder

| Tier | What it is | Signal to a recruiter/engineer |
|---|---|---|
| **Tutorial** | Followed a guide; predictable result | ~none; everyone has these |
| **Demonstration** | Own build, works, but small scope / no real users / demo-only | shows basic capability |
| **Strong portfolio** | Real problem, real build on real hardware/data, documented, honest metrics, defensible decisions | shows engineering judgment |
| **Industry-credible** | Solves a real-world need, has depth/architecture, testing, deployment/reproducibility, ideally users or a real product context | reads as professional work |

## Scoring axes (each project)
Rate 1–5 on: **real-world usefulness · technical depth · architecture · relevant tech · measurable outcome · documentation · testing · deployment/reproducibility · demonstrability · differentiation · defensibility (can you explain every decision in an interview).**

## What lifts a project up a tier
`[REC, High]`
- Demonstration → Strong: add documentation (README to the repo standard), a real metric, honest ownership, an architecture diagram, and a demo video.
- Strong → Industry-credible: add tests + CI, deployment/reproducibility, and depth (a second subsystem, real users, or a hard trade-off handled).

## Selection rule
`[REC, High]` Do **not** include every project. Feature the 3–4 that are Strong+ and on-identity; keep Demonstration-tier and off-theme ones off the resume/portfolio (or brief mentions only). More weak projects lower the average signal.
