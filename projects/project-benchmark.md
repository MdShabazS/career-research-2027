# Project Benchmark — what credible projects look like

Market evidence on what makes projects count, applied as a benchmark the candidate's projects are measured against in [`project-gap-analysis.md`](project-gap-analysis.md).

## 1. The consistent market message
- `[FACT, High]` "**2–3 well-documented projects on real hardware worth more than ten shallow undocumented ones.**" Projects must run on real hardware (embedded) or ship to production (AI), with GitHub docs, comments, and design rationale. (piestsystems.)
- `[FACT, High]` AI hiring: "built at least 2–3 ML projects that solved a real problem, not a tutorial" and can **ship a model into production, not just a notebook.** (masaischool, taggd.)
- `[FACT, High]` Fresher resume guidance: 3–5 projects, quality over quantity, each with build + stack + measurable outcome + GitHub link. (resumevera, careerskraft.)

## 2. Credible-project ingredients (recurring)
`[INFER, High]` real-world usefulness · runs on real hardware / real data · documented (README, diagram, decisions) · honest measurable outcome · testing where relevant · reproducible/deployable · demonstrable (demo/video) · defensible in an interview.

## 3. What recruiters discount
`[INFER, High]` Tutorial clones, undocumented repos, notebook-only "projects" with no deployment, team projects presented as solo, and empty scaffolds. (piestsystems, readmedesign; reference-repo audit found an empty flagship scaffold — a live example of this anti-pattern.)

## 4. Embedded-specific credible-project templates
`[FACT, High]` (piestsystems) CAN network simulation with PCAN; sensor validation test harness with automated pass/fail; ESP32→MQTT IoT dashboard; Linux kernel module driving GPIO/I2C. These map directly onto the candidate's next-build options.
