# Portfolio — Engineering Storytelling

How to make the portfolio communicate *engineering capability*, not just visual polish. This is what turns "nice template" into "this person builds real systems."

## 1. Each project = a problem→decision→result story
`[REC, High]` Per case page: **Problem** (who needs it, why) → **Approach/architecture** (a diagram) → **Key engineering decisions & trade-offs** (e.g. non-blocking `millis()` scheduler vs blocking delays; confidence-gating + temporal smoothing in VisionPay) → **What I built** (honest contribution vs team) → **Status & evidence** (repo, demo, real media) → **What I'd do next**. The *decisions* section is where engineering judgment shows.

## 2. Show the mechanism, not just the outcome
`[REC, High]` The strongest signal for an embedded engineer is a **working mechanism made legible**: an interactive state machine, an annotated wiring diagram, a signal/timeline visualization. Diagrams that show the *real* mechanism beat decorative 3D. (Consistent with the 3D research: 3D as evidence.)

## 3. Honesty as a feature
`[REC, High]` Label statuses truthfully (AEGIS = design stage; Smart Wellness = team; ~93% = reported). Honesty is a credibility signal, and it prevents the interview-screen failure that inflated claims cause. A "what I'd do next / known limitations" section reads as senior, not weak.

## 4. The one differentiator to foreground
`[INFER, High]` The candidate's distinctive combination is **embedded firmware + on-device computer vision** (VisionPay: offline CPU inference; MITRA: on-device stream/vision app work). Few freshers pair real hardware firmware with real edge-AI. Make that the throughline of the hero and the project ordering — it is the memorable, defensible identity.

## 5. Voice
`[REC, High]` Plain, specific, first person. No "passionate about leveraging cutting-edge technology." Let the real work and real numbers carry it. (Matches the reference repo's own writing rules.)

## 6. Recruiter-vs-engineer dual read
`[INFER, High]` The story must land in 5 seconds (hero line + one image) AND reward a 5-minute deep read (architecture, decisions, repo). Storytelling is what bridges the two audiences on one page.
