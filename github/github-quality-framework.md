# GitHub Quality Framework

Four tiers, from the brief. Never recommends fake activity, fake commits, artificial graphs, copied repos, or inflated stats (brief §9).

## The ladder

| Tier | Profile README | Pinned repos | Per-repo README | Engineering signals | Honesty |
|---|---|---|---|---|---|
| **Superficial** | none / badge wall | many half-finished, bad names | one-line or none | none | may include forks-as-work, streak-gaming |
| **Acceptable** | short, honest identity | 3+ finished repos, decent names | purpose + setup + stack | runs locally | truthful, plain |
| **Strong** | identity + goal + capability | 3–4 polished, demo where possible | + screenshots, decisions, usage | tests, meaningful commits, topics | ownership clear (team vs solo) |
| **Elite** | tight pitch, links out | 4–6 best, live demos | + architecture/diagrams, reproducible | CI, issues/PRs/releases, a real OSS contribution | fully honest, contribution attributed |

## Scoring a profile
`[REC, High]` The profile's tier ≈ the tier of its **pinned repos** (the thing recruiters actually open). A great README over weak repos is still Acceptable at best.

## The honesty firewall (hard rules)
`[REC, High]` No fake/meaningless commits, no artificial contribution graphs, no copied/forked-as-original repos, no fake projects, no inflated stats/vanity widgets presented as achievement. A team project is labeled a team project; the candidate's contribution is stated. Streaks are irrelevant — do not chase them.

## What actually moves a fresher up a tier
1. Turn each existing project repo into a **Strong per-repo README** (purpose, setup, stack, screenshot, decisions, honest contribution). Cheapest, highest-impact.
2. Add a **screenshot/GIF** of each project working.
3. Add **tests + a GitHub Actions CI** to one repo → a genuine Strong→Elite signal.
4. One small **real OSS contribution** (a doc fix, a bug fix) → credibility no solo repo gives.
5. A concise, honest **profile README**.
